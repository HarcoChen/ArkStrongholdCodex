# ABYSS：从阵营成长到实际战力

整理于 2026-11-02，增补至 2026-11-12，来源为实战观察与复盘，不是对照试验、最优解或胜率证明。具体机制须以当前站点的公开说明、合法可见状态和实际事件复核；以下检查不授权开新局、读取隐藏信息、改游戏或执行训练。沿用主 skill 的工具批次、revision、挂起等待及每轮一次战斗统计规则。

## 1. 把主轴与辅助分开记账

- 先写阵营主轴、场上不同成员数、已激活档位、层数、成长卡和实际主输出，再写精准、灵巧等辅助。重复副本、整备区成员和金棋数量不能替代不同成员数。
- 主轴成长能兑现时主动经营，不以辅助高层数代替它；但不能为追主轴的绝对层数拆掉生存或有效输出。跨阵营层数不能直接比较强弱。
- 查实际禁用棋子和可见候选；盟约禁用不能自动推导为全部成员都不可获得。高档效果、转职资格、部署空间分别核对；物品有赋予盟约字段也不等于当前目标允许转职。
- 检查放大效果到底选中谁。例如号角可能支持层数最高的其他已激活盟约；空弦要核对朝向、前格对象与阶段；薄绿看不同阶，不看重复副本。

## 2. 先预算，再算成长

- 按当前价格逐项算买牌、刷新、升本、第三张合成所需金币，连同手牌容量和部署空间一起比较。留住购买可见关键成员和当轮生存的预算；升本不自动代表增加人口，也不回溯抬高已经生成的奖励。
- 有可负担的成长入口时尽早启动，但不设统一的 R3 等死期限。早晚取决于实际出现的牌、阈值、血量和转型代价，不能为凑标签耗尽经济。
- 分开记立即获得事件、阶段末获得计数、技能/耗弹/控制事件；核对当前激活条件与倍率。小满/夕的阶段末计数要包含本轮实际获得，卖出不必然撤销计数，合成也不凭空重复算一次。
- 同一张棋子可能同时贡献“自身获得时立即加层”和“小满/夕按本轮获得数结算”，须列出两个独立机制，不漏算也不重复记同一事件。动作后以返回状态确认已到账层数；阶段末预估另列。
- 商店金币与战斗部署资源分账。装备、金棋投资优先回答“谁能持续输出、谁让输出存活”，不只追金棋总数。复制/拟态等物品在满装备位时先确认替换规则，避免覆盖主输出关键装备。

## 3. 战前问四个问题

| 问题 | 必查证据 | 常见误判 |
| --- | --- | --- |
| 谁真的打得到？ | 当前敌波运动类型、实际路线与停留、攻击范围、合法目标、全体友军阻挡、技能触发对象 | 地图有飞行路线就当本波飞行；满技力就当自动开技；忽视治疗/辅助抢先阻挡 |
| 谁会被打？ | 敌人接近与射击范围、普通选敌与独立技能选敌、移动中的危险范围 | 坦克不在敌人合法选敌范围仍期待嘲讽；只看最终阻挡点，不看接近途中 |
| 谁真的能被奶？ | 治疗范围、目标资格、不可治疗/隔离状态、有效吞吐、奶自身存活 | 两奶就默认互保；把零阻挡、飞行或不可治疗召唤当普通可奶坦克 |
| 主输出何时停工？ | 接敌、攻击、技能、控制、倒地/回归和 Boss 阶段时间线 | 全队存活就认为输出连续；把辅助金棋数或总层数当击杀能力 |

维娜 S3、凯瑟琳 S2 等自动技能先核对各自合法触发对象；附近有无法攻击的飞行敌人、或旁边友军挡敌，不是通用开技保证。用实际攻击次数、技能状态和目标验证，不只看 SP。必须实际阅读几何/路线校验的返回内容；`UNVERIFIED`、报错或不支持均标为“未验证”，不能把工具运行过当作验证成功。若工具未提供足够证据，就保留“未验证”，不能凭推测宣布就绪。

## 4. Boss 检查按当前公开机制展开

- 最高攻击目标诱弹：检查属性动态变化与目标周围波及区，避开双奶/核心；导弹抵达爆炸后 HP 归零不能证明途中被拦截。
- 移动范围伤害：检查整个接近、冲锋、停射与阻挡过程，不只比较终点格子。
- 随机十字等独立选敌：检查全部合法目标与自动召唤物，嘲讽不能替代隔离验证。可比较放弃某个危险召唤收益，但只执行当前规则允许且用户已授权的布置。
- 列攻击与阶段转换：前排存活不代表同列后排安全；尚未进入的阶段不能解释此前输出不足。
- 分开寒冷、冻结免疫、脆弱、直接眩晕抗性和元素积累预防。元素爆发后存活不等于全程免疫；确认某个召唤继承自损也不能推广为继承全部装备钩子。

## 5. 复盘证据分层

1. **事实**：权威结算、实际部署/属性、可见动作返回、已观察攻击/技能/伤害事件；注明统计覆盖和单位归属。
2. **推断**：依据时间线提出“可能由接敌、控制或生存窗口限制”，同时写仍缺什么证据；相关性不单独证明原因。
3. **未验证**：缺失的时间段、未到的阶段、假设站位和跨版本机制，不用确定语气填补。

保留 `pending`、`unavailable`、`complete:false`、重建或强制结束等来源标记；不重复查询同一已结束战斗来“刷完整”。结算胜负与统计完整性分别报告：不完整报告不抹掉已确认结算，最后采样 HP 也不能覆盖权威结算。

对敌总伤害可能包含小怪，不等于对某个 Boss 的伤害；召唤归属按工具口径，不重复相加。区分普通漏怪、超时残敌、延时结算与 LP 变化。一次成功只说明当时配置可行，不证明稳定通关；失败时先定位输出停顿与掉血的先后，不把末尾倒地解释成此前整段低输出的原因。

## 6. 将范围与阻挡落实到逐人检查

先记录当前实例的 `rangeGrid`、`rangeId`、技能范围变化、`stats.blockCnt`、位置与朝向，再读取本波实际路线与敌人属性。接口未直接给出“能命中谁”，不等于看不到范围；不要用职业印象替代验算。

- 将相对覆盖格旋转并平移为绝对格，区分工具坐标、界面坐标和地图行列方向。先用已知相邻格校验一次转换，再检查敌人运动全过程的射程交集与驻留时间；不要只画最终阻挡点。
- 2026-11-11 查阅的缓存实现以 row 0 在底部、偏移为 `(dr,dc)`：RIGHT 为 `(dr,dc)`，UP 为 `(dc,-dr)`，LEFT 为 `(-dr,-dc)`，DOWN 为 `(-dc,dr)`。缓存未绑定线上版本 SHA，必须先核对当前接口约定，不能当作跨版本保证。
- 同份缓存用普通敌人碰撞体与范围格求交，大型 Boss 另有 `hitArea`。中心格不在范围不一定等于打不到；反之，几何交集也不保证地空、隐匿、选敌或技能条件合法。
- 缓存选敌对被阻挡目标有优先路径，不能因其不在普通范围格就直接排除攻击；治疗仍按治疗目标逻辑核实。用实际攻击事件验证特殊技能或版本差异。
- 核对已占阻挡容量与敌人 `blockWeight`，不要只数人头。例如容量 3 已挡住权重 1 的敌人，不等于还能接下权重 3 的敌人。再查地空、不可阻挡、接触、倒地和接力位置，不能推广为所有 Boss 都可被挡。
- 全体友军都纳入检查，尤其是提前挡敌的治疗/辅助。对主C分别列“能打的路径段”“可能被谁抢先挡住”“自动技能合法触发对象”“接敌前生存预算”；前置承伤不能预先记为输出。
- 对治疗同时检查绝对范围、目标资格（如 `noHeal`）、奶自身存活和有效吞吐。范围验算通过不代表实战一定受到治疗；报告的 `healing` 是造成的治疗，不能由坦克该值为 0 推断没人奶它。

## 7. 身份、装备与自伤：先核实再投资

- 购买、三选一、合成奖励和部署前核对当前 ID、名称、职业/技能、白金形态，不由别名或原作印象猜角色。曾将吟游者误认作输出位；发现后应重算其当前价值，而不是用金棋数掩盖主C缺口。
- 核对实际装备槽数与被替换者。近期对局为两格，第三件会替换旧物；消耗品即使用后消失，也可能先挤掉浓茶等关键装备。使用前写出“旧组合 → 预期新组合”，使用后读实际状态，不能继续声称已被替掉的回技组合生效。
- 不把请求中的替换标识当作动作成功证明：曾在仍有空格时新增了物品而未卸下原自伤物。按工具支持的合法流程处理，开战前确认目标物确实消失。
- 2026-11-11 核实的源石溶剂数据为攻击力 +40%（金色 +60%），每秒 60 点自伤，**不是攻速加成**。当前说明或版本不同则重新确认；不要只凭物品名称或旧记忆装备。
- 用当前 HP、自伤速率、接敌前等待、护盾/减伤和实际治疗估算能否活到首次攻击。某局“0 次攻击、承伤接近初始 HP”支持接敌前死亡的假说，但没有来源事件时不能单独证明自伤，也不能排除敌方攻击。
- 对敌人类友方召唤物单独核实周期自伤关联、治疗资格与继承规则。缓存说明提示某些召唤可能受同类周期伤害影响，但线上版本未核实；不能泛化到所有召唤，也不能把召唤倒地全部归给 Boss。
- 区分物品文案“流失”与实现中的伤害类型；是否触发受击、护盾或减伤，用当前公开实现/事件复核，不从总承伤倒推。

## 8. 用时间顺序避免错误归因

先比较“Boss HP 下降开始变慢”“主C首次攻击/开技”“控制或首倒”的先后。已有失败局在全员满血时击杀进度就明显不足；末段死亡不能解释此前全部低 DPS。反之，纸面层数高或普通关完美也不代表 Boss 输出充足。

当战报完整且提供事件时，结合攻击次数、技能状态、目标与 HP 曲线定位问题；低攻击次数本身仍不能区分没接敌、被控制、目标非法或其他机制。对 `forced`、`reconstructed`、`complete:false` 保留标签，不把片段拼成完整时间线。只提出证据支持的改进假说，不宣称唯一败因，也不把不同地图、Boss、阵容的胜败当作受控因果试验。
